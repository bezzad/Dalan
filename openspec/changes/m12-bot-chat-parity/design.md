# Design

## Context

Found by running ArcaneBot on Dalan (@mofidbot, bot id 4) beside Telegram Desktop. The Bot API names come from Telegram.Bot 22.10.4 (Bot API 9.x); core.telegram.org is not reachable from the owner's PC. Addresses: owner, 2026-11-23 (`/bots` = My bots, chats move to `/chats`).

## Decisions

1. **Keyboard options live with the keyboard, not as new columns.** Message content is jsonb. `ReplyKeyboard` gets `Persistent`, `Resize`, `OneTime`; a button becomes `{text, style?}`. `InlineKeyboardButton` gets `Style`. Old rows (plain strings) still read. Contracts: `ReplyKeyboard(List<List<KeyboardButton>> Rows, bool Persistent, bool Resize, bool OneTime)`, `KeyboardButton(string Text, string? Style)`, `InlineButton(..., string? Style)`. A style other than `success`, `danger`, `primary` is 400 `bad_keyboard` (Telegram refuses it too).
2. **Client JSON keeps old fields.** `reply_keyboard` stays `string[][]` (old clients and REL-17 tests keep working); new `reply_keyboard_options: {persistent, resize, one_time, styles: (string|null)[][]}` only when one of them is set. Inline buttons get `style`. The `/v1` Bot API accepts a button as a string or `{text, style}`, and the three flags as `reply_keyboard_persistent`, `reply_keyboard_resize`, `reply_keyboard_one_time`.
3. **Keyboard place and behaviour (client).** The keyboard sits under the input bar, in the place of a phone keyboard. `resize_keyboard` false: the keyboard takes a fixed height (`--keyboard-height`, about a phone keyboard, at most 40% of the screen) and rows share it; true: each row is as tall as a button. `one_time_keyboard`: hidden after a tap, the ⌨ button in the input bar shows it again. `is_persistent` false: the ⌨ button hides and shows it; true: it cannot be hidden and has no ⌨ button. Hidden or shown is kept per chat in memory only.
4. **Rows.** Each row is its own flex line; its buttons share the row width equally. No wrap. Long text breaks inside the button. Colours: `success` = `--brand`, `danger` = `--danger`, `primary` = new token `--primary` (blue), set for both themes in `app.css`.
5. **Voice recording.** `MediaRecorder` with the first type the browser supports of `audio/ogg;codecs=opus`, `audio/webm;codecs=opus`, `audio/mp4`. WebM/Opus is remuxed on the device into Ogg/Opus by a small pure function (`client/src/ogg.ts`: read the EBML blocks, write Ogg pages with `OpusHead` and `OpusTags`); no transcoding, so it is fast and tested with a saved sample. If that fails, the WebM is sent as `audio/webm`. `audio/mp4` (Safari) is sent as it is. The upload adds header `X-Voice-Duration: <seconds>`; with it the server stores kind `voice` (any `audio/*` type), else the type rules of REL-28 stay. The length comes from the recorder clock, rounded. The maximum is the file size limit; the bar shows the time.
6. **Durations.** New nullable `relay.files.duration` (seconds). Set by the user's voice upload and by a bot's `duration` parameter on `sendVoice`, `sendAudio`, `sendVideo`. The Telegram JSON gives the stored value, else 0 as today.
7. **Voice player.** Our own small player (play/pause, a seek bar, time), not the browser's `<audio controls>`: the browser one is wide and differs per browser. It reads the stored duration first (WebM and Ogg often have no length header).
8. **Paste and drop.** `paste` on the input and `drop` on the chat take the first file. Before sending, a small card above the input shows a preview (image) or name and size, with the input as the caption field, Send and Cancel. 📎 goes through the same card. The type rules of REL-28 decide photo or document; a pasted image keeps its type (`image/png`), named `image.png`.
9. **One bot icon.** New columns on `relay.bots`: `icon` (bytea), `icon_type`, `icon_version` (int, grows on each change, used as `?v=` so caches stay correct). The migration copies each showcase icon to its bot and drops the showcase icon columns. Setting the icon does not send the showcase entry back to review (Telegram has no review either; the admin can still suspend a bot). Endpoints: `PUT/DELETE /api/builder/bots/{id}/icon` (owner or admin), `GET /api/bots/{id}/icon` (no session: like a Telegram profile photo, it is public while the bot is not deleted or suspended). `GET /api/showcase/{id}/icon` stays as an alias for listed bots. Bot JSON in the chat list, the link page, the builder list and the showcase gets `icon_version` (0 = no icon).
10. **Crop on the device.** The icon picker draws the picture centred and cut to a square on a canvas, 512 by 512, and saves JPEG at falling quality until it fits `Relay:MaxBotIconKb`. The server does not decode images; it checks the first bytes (PNG, JPEG, WebP) and the size, as REL-41 does today. A bot's own upload by `setMyProfilePhoto` is not cropped: the client shows every icon with `object-fit: cover` in a circle.
11. **Builder ways to set the icon.** REST above; MCP tool `set_bot_icon` (`bot_id`, `image_base64`); CLI `node dalan.mjs icon <bot id> <file>`. All go through `BuilderBots`.
12. **Addresses (CLI-51).** The router reads the address only; no hidden panel state. `/chats` chats, `/bots` my bots, `/bots/new`, `/bots/<username>`, `/account`, `/admin` (admins only, else `/chats`), `/apps`. The server already serves `index.html` for unknown paths (ClientApp.cs). The service worker keeps `/` as the page for every navigation, so nothing changes there. Old links: `/bots` for a user who is not a builder shows the builder step card (CLI-23 text) on the My bots page.
13. **Bot page and token.** `/bots/<username>` loads the bot from `GET /api/builder/bots` by username (no new call). The token from create or rotate is kept in memory with its bot id, shown only on that bot's page, and gone on Close or leaving the page. The guide on this page is built from this bot only: `username`, `id`, link, and the token or `<id>:<TOKEN>` (the placeholder keeps the real id). Tabs: Telegram bot (the seven library samples, CLI-38), CLI, MCP.
14. **Text size (CLI-48).** Telegram Desktop at 100% scale: message text 14px, line height about 1.35, bubble padding 6px 10px 6px 12px, time 12px, the time on the last line when it fits. Persian uses Vazirmatn at the same px size. The exact numbers are checked against a screenshot of Telegram Desktop next to Dalan at the same window width (task 5.2); the owner's screenshot wins over these starting values.

## Risks

- `MediaRecorder` needs HTTPS and a microphone permission. Without them the 🎤 button is hidden.
- A remux bug would make a broken file: the remuxer is tested with a recorded sample, and ArcaneBot (ffmpeg + whisper) is the end check.
- Moving showcase icons is one-way; the migration's Down puts them back from the bot.

## Settings

None new. `Relay:MaxBotIconKb` (start 100) now limits the bot icon; `Relay:MaxFileSizeMb` limits a voice.
